Terminology

Nnum_envs
PPO sets up a vectorized environment that runs N (usually independent) environments, either one after another or in parallel (source). These are the rows in the grid below (env 0, env 1, env 2).
Mnum_steps
Called nsteps in the original code. The agent steps the N environments for a fixed M steps per rollout. This is the length of one segment: the width of one phase block in the grid.

1 Vectorized environments

The key point: the rollout boundary and the episode boundary are separate, and two variables, next_obs and next_done, keep track of both.

What to notice

  • Rollout boundaries are fixed. Every M steps, collection stops and learning starts, no matter where any episode is. An episode (one color) can run straight through a boundary. Env 2 is one long episode that never ends.
  • next_obs connects the phases. At the end of phase j, the environments have already been stepped once more. That extra observation (dashed box) has two jobs:
    • During learning, it supplies the value at the end of the segment. Each env's return ends with V(next_obs), because the trajectory was cut off, not because it finished.
    • In the next rollout, it becomes data[0] of phase j+1 (solid box). Nothing is reset; stepping just continues.
  • next_done says whether that observation is the same episode. The black bar marks the first observation of a new episode.
    • After phase 2 (step 12), env 1 has next_done = 1: its next_obs belongs to a new orange episode. Bootstrapping from it would leak the next episode's value into the old one's return, so (1 − next_done) zeroes it.
    • After phase 3 (step 18), env 0 hits the same case. Env 2 always has next_done = 0 and always bootstraps.
  • The same mask cuts GAE inside a phase. Wherever an episode ends mid-phase, (1 − done) stops the advantage from flowing across it: env 0 at step 9, env 1 at step 4.

Put together

The agent always learns from M-step segments, and next_obs / next_done handle the edges. PPO never needs an episode to end before it can train, which is why it can handle a game whose single episode lasts 100,000 steps: env 2, stretched out.

2 Orthogonal initialization of weights, constant initialization of biases

In general, the weights of hidden layers use orthogonal initialization with scaling np.sqrt(2), and the biases are set to 0.

5 Generalized Advantage Estimation (GAE)

PPO uses GAE to estimate the advantage: how much better an action turned out than the value function expected. Rather than trusting either a one-step guess or the full sum of rewards, GAE blends them with a single knob, λ.

It's built from one-step TD errors, the "surprise" at each step:

δt = rt + γ·V(st+1)·(1 − donet+1) − V(st)

The advantage is a decaying sum of the δ's that come after it, cut off where the episode ends:

At = δt + (γλ)δt+1 + (γλ)2δt+2 + …
computed backward as  At = δt + γλ·(1 − donet+1)·At+1

What to notice

  • λ slides between two extremes.
    • λ = 0 gives At = δt, a one-step TD estimate. It has low variance, but it leans heavily on V, which may be wrong.
    • λ = 1 sums every δ to the end of the segment, which works out to the discounted rewards plus the bootstrap, minus V(st). It depends less on V, but it's noisier. PPO's default, gae_lambda = 0.95, sits near this end.
  • One backward pass is enough. Each At only needs δt and At+1, so the loop runs reversed and carries lastgaelam from one step to the next.
  • The edges come from section 1. At the last step, the loop uses next_value and next_done, from the next_obs carried across phases. Inside the segment, dones[t + 1] cuts both the bootstrap and the chain. Step to t = 4 to see the advantage stop at the episode boundary.
  • Returns come for free. returns = advantages + values are the targets for the value function. This is the TD(λ) return.

Put together

GAE turns each step's surprise δ into an advantage by adding up the surprises that follow, discounted by γλ and stopped at episode ends. PPO computes all of them in a single backward loop over the rollout.
