  1. Vectorized environments: next_obs and next_done

1 Vectorized environments

The key point: the rollout boundary and the episode boundary are separate, and two variables, next_obs and next_done, keep track of both.

What to notice

  • Rollout boundaries are fixed. Every M steps, collection stops and learning starts, no matter where any episode is. An episode (one color) can run straight through a boundary. Env 2 is one long episode that never ends.
  • next_obs connects the phases. At the end of phase j, the environments have already been stepped once more. That extra observation (dashed box) has two jobs:
    • During learning, it supplies the value at the end of the segment. Each env's return ends with V(next_obs), because the trajectory was cut off, not because it finished.
    • In the next rollout, it becomes data[0] of phase j+1 (solid box). Nothing is reset; stepping just continues.
  • next_done says whether that observation is the same episode. The black bar marks the first observation of a new episode.
    • After phase 2 (step 12), env 1 has next_done = 1: its next_obs belongs to a new orange episode. Bootstrapping from it would leak the next episode's value into the old one's return, so (1 − next_done) zeroes it.
    • After phase 3 (step 18), env 0 hits the same case. Env 2 always has next_done = 0 and always bootstraps.
  • The same mask cuts GAE inside a phase. Wherever an episode ends mid-phase, (1 − done) stops the advantage from flowing across it: env 0 at step 9, env 1 at step 4.

Put together

The agent always learns from M-step segments, and next_obs / next_done handle the edges. PPO never needs an episode to end before it can train, which is why it can handle a game whose single episode lasts 100,000 steps: env 2, stretched out.

Where this lives in the code (CleanRL ppo.py, simplified) 
# carried across rollout phases, never reset between them
next_obs  = envs.reset()
next_done = torch.zeros(num_envs)

for update in range(num_updates):
    for step in range(num_steps):                 # M steps per phase
        obs[step]   = next_obs                    # data[0] = last phase's next_obs
        dones[step] = next_done
        action, logprob, _, value = agent.get_action_and_value(next_obs)
        next_obs, reward, next_done, info = envs.step(action)

    # learning: bootstrap from next_obs, masked by next_done
    next_value = agent.get_value(next_obs)
    lastgaelam = 0
    for t in reversed(range(num_steps)):
        if t == num_steps - 1:
            nextnonterminal = 1.0 - next_done         # edge of the segment
            nextvalues      = next_value
        else:
            nextnonterminal = 1.0 - dones[t + 1]      # episode ended mid-phase
            nextvalues      = values[t + 1]
        delta = rewards[t] + gamma * nextvalues * nextnonterminal - values[t]
        advantages[t] = lastgaelam = delta + gamma * gae_lambda * nextnonterminal * lastgaelam
